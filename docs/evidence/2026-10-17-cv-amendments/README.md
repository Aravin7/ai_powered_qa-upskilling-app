## Reproduce

Use pinned Node 24.19.0, installed dependencies, an isolated migrated test database and a Chromium installation. Set `TEMP` and `TMP` to an ignored writable test directory on Windows if the sandbox's temporary module cache is unstable. The local nvm shim failed its integrity check earlier in this session; commands were invoked through the pinned Node executable directly.

```powershell
# Unit/parser/provider checks (no external AI):
node node_modules/vitest/vitest.mjs run --maxWorkers=1 tests/unit.test.ts tests/ai.test.ts tests/qa-coverage.test.ts tests/groq-provider.test.ts tests/cv-minimization.test.ts tests/groq-controls.test.ts
node node_modules/typescript/bin/tsc --noEmit

# Configure TEST_DATABASE_URL to an isolated, migrated database first.
node node_modules/vitest/vitest.mjs run --maxWorkers=1 --testTimeout=15000 tests/integration/qa-coverage.test.ts -t 'CV-'

$env:RUN_AUTHENTICATED_E2E='true'
$env:ENABLE_SYNTHETIC_PILOT='true'
$env:E2E_PORT='31417'
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
node node_modules/playwright/cli.js test tests/e2e/connected.spec.ts
```

The Playwright configuration supplies mock mode and generated test secrets; the journey writes these three screenshots to this folder. Never point `TEST_DATABASE_URL` at a personal/production database. The test uses existing session encoding solely within its runner; no public authentication bypass was added.
